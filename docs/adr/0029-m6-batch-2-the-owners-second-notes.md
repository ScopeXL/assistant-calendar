# ADR 0029: The owner's second notes (M6, batch 2)

- **Status:** Accepted
- **Date:** 2026-10-12

## Context

- Sunroom 0.7.0 went on the owner's wall and phones, and after a few more days of use they sent
  a second set of notes. `docs/M6-batch-2.md` turns them into tasks; the decisions below were
  made with the owner on 2026-10-12 and settled while building them (PLAN §15, M6 → 0.8.0).
- Until now each room drew its own title row, the rail held the clock and the weather, and the
  Today panel hid in Settings. The owner wants one bar across the top that is the same in every
  room, with the page's own buttons at its right.

## Decision

| Question | Decision |
|---|---|
| "Chores" | The family reads **Tasks** and **task** everywhere: the room, the Add type, the Today panel's block, Settings, tips, toasts and error copy. The stored word stays, as Kid did under Child (ADR 0028): the plugin id `chores`, its routes, tables, events, query keys and the room's address `/chores`. No migration and no API change |
| The people view's name | **People**, one word beside Week · Day · Month, in the view switch, the Home view setting, tips and the docs. "Who's Doing What" is gone |
| Small text | A fourth text size, Small: the root font size at 87.5% (14 px), for a screen around 1920×1080 that is read up close. The display's floor is 16 px there (18 at Standard stays the rule); `text_size` is a string column, so the value needs no migration |
| Tap targets at every text size | A target grows with Large and Extra large and never shrinks under Small: `--tap` is `max(3.5rem, 56px)` and `--tap-primary` is `max(4rem, 64px)`, in the theme's spacing scale as `min-h-tap`, `size-tap`, `min-h-tap-primary`. The least room between two targets holds the same way: `--spacing-2` is `max(0.5rem, 8px)`, so every `gap-2` keeps 8 px. The Hours grid, which sizes chips in JS, floors them with `tapPx(rem)`. Small shrinks text and spacing, never a target |
| Button groups | Each word in a segmented control has 20 px of room on either side on the wall and 16 on phones (it was 12). A group that can't fit one line wraps onto a second row with a fixed corner radius, so it still reads as one control. `IconSegmented` is the icon form: round tap-sized cells, no border, each named. A setting's choices are a group up to six options and 40 letters; more are chips |
| The header | One bar over the board and the Today panel, the full width in portrait (it replaces the portrait band's clock strip, and the band drops from 28rem to 24rem). Zones: today (the date, the time at 40 px in digit boxes with AM or PM beside it, the weather) · the room's way back, title and controls · the Today panel's button · the live-updates icon at the far right (ADR 0028's corner holds). One row from 104rem of the header's own width (1920 px at Standard and Small), two rows below it: the room's part moves to the second row and the corner stays put. The rail stays full height and loses its clock |
| The title's quiet line | Under the title, not beside it. Side by side, the week's span ("Sep 27 – Oct 3") is as long as the title, and with the chosen view's word in the switch the one row no longer fit at 1920 px Standard. Stacked, the worst case (late September, a two-digit hour) fits with room to spare, and portrait's second row holds the title, the arrows and the switch |
| How a room reaches the header | A store, `shell/roomHeader`, set in a layout effect on every render and cleared on leaving (`useRoomHeader`, or `<RoomHeader title="Lists" …/>` so the Title Case test reads the literal). Not a portal: a portal needs the header's node before the room first renders, and the kiosk remounts the shell between `/display` and the rooms, which would blank it. The header is the store's only subscriber. Every room uses it; none draws a title row |
| The Today panel in Settings | Allowed now: its button is in the header in every room, and Settings' pages are capped at a reading width anyway |
| The view switch | Four icons (Week · Day · Month · People) with the chosen view's word beside its icon while the header has 64rem; below that one **View** button named "View: Week" that opens the four as a menu of radio items (the checked one takes focus, arrows move, Escape, Tab and a press elsewhere close it and return focus). No library, no `<dialog>`. Only one form is drawn at a time, so a button named "Day" is never there twice |
| The rail's top and its fold | The rail starts with the brand (the mark over the name) and **Hide the rail**. Folded, it is an icon-only mini rail, 4.5rem wide: the mark, **Show the rail**, each room, the Add circle and Settings, every one still named. It is never fully hidden, so a room is always one tap away. The width is one CSS rule, `:root:has([data-rail="compact"]) { --rail-w: 4.5rem }`, so the header, the board and the toasts follow with no script; landscape only, portrait's bar is always whole |
| How long a fold lasts | A per-screen override in the display state (`railCollapsed`), cleared by the two-minute idle reset like the Today panel's, over a household setting, **Compact rail** (`display_rail_compact`), for a lasting choice. With the setting on, Show the rail opens it out until the next idle reset. The width eases over the enter time, never on first paint: the attribute that allows it arrives a frame after the settings do |
| Gear or padlock | Settings is a gear. It is a padlock only while Settings are locked: a paired screen with a PIN set and no grant open. A parent's laptop and a household with no PIN see the gear from the start; with a grant open the word under the gear reads "Unlocked", and the header's own Lock button keeps its padlock. The button carries `data-icon`, because lucide puts no class on its SVGs for a test to find |
| Toasts and the rail's side | The wall's toasts sit over the board: between the rail and the Today panel, whichever side the rail is on and whether or not the panel shows (four static class sets in `ToastRegion`). Batch 1's follow-up, closed |
| The Hours zoom | Buttons, not a ladder of named levels (this supersedes ADR 0028's 24h · 12h · 1h · 15m): **Zoom out · Fit the day · Zoom in** in the board's toolbar while Hours is on. The zoom is a number in the display state: 1 fits the whole day with nothing to scroll, the default, and each tap is ×1.5 along one ladder (`features/calendar/hours.ts`), so in then out comes back exactly. It stops at the first step where a 15-minute event gets a full chip (`maxZoom`, from the grid's height and the text size, which only the grid can measure: it publishes the limit in `hoursMaxZoom` for the button). The gutter's labels and the faint lines follow the pixels per hour, not a level. Ctrl + wheel on the grid, which is also what a trackpad pinch sends, is a shortcut with the buttons as its twins. A two-finger pinch on the kitchen screen's touch panel is not built: it can't be told from the long press that lifts a chip without trying it on that panel |
| Add: the kinds | One row at the top of the panel, each cell the room's own icon over its word (`AddType.icon`), the chosen one filled: a stacked `Segmented`. It never wraps; where five cells don't fit (a phone) the row scrolls sideways with a fade at its edge |
| Add: one form per kind | Every form shows each of its choices on its own row, with nothing behind a chip that has to be opened first, and the primary button pinned at the bottom (`ui/PanelActions`). The event form keeps the quick-add field: typing fills the rows, a row set by hand wins over later typing, and the line under the field says what's left as the title. The "Understood as" sentence and the one-picker-at-a-time chips are gone |
| The Who row | Always one row (`ui/WhoPicker`, `lib/fit`): cells share the width from 64 px avatars; when the people don't fit, everyone takes 56 px; when even that doesn't fit, the row scrolls sideways. Names are cut on screen only. "Who did it?" in a board column is the one place it still wraps |
| Picking a day | `ui/DayField`: the week as seven cells in the household's order, Previous week, Today, Next week, and Pick a date for a month grid in place. No native date input on the wall or on phones: one code path and one set of names, and the kitchen screen has no way to work a system date dialog. (A person's birthday in Family still uses the native field: a date decades back is a poor fit for a month-by-month grid) |
| Picking a time | `ui/TimeField`: a chip for no time ("All day", "Any time"), the likely times, and Pick a time for the hours and minutes in place. The chosen time is always a pressed chip on the row, in clock order, even when it isn't one of the suggestions |
| Custom repeats | Every N days, weeks, months or years; for weeks, any weekdays, listed in the household's order; for months, the date or the nth weekday; ends never, on a date or after N times. Steppers, not typed numbers. They compile to the same RRULE shapes as the presets and read back (`repeat.ts`) |
| A rule the editor can't read | Kept exactly as it is (`Draft.kept`, a task's `kept`), shown as a pressed "As it is: …" chip with the server's words, and sent back unchanged. Before, opening such an event and saving its title cleared the rule |
| The week's first day in a rule | Written as `WKST` only when it changes the rule's days: every few weeks, on weekdays either side of the household's first day (`weekStartMatters`). A rule is read only when its own first day means the same days as the household's; otherwise it is kept as it is. "Every 2 weeks on Tue and Thu" is the same days either way and stays readable |
| The panel around the forms | A field in the wall's side panel needs only a little scroll margin (the panel's own scroll padding already holds the keyboard): counted twice, the field jumped to the top and pushed the row of kinds out of view. The panel opens at its top each time, a picker that opens low scrolls into view (`lib/reveal`), and the pinned button hangs a strip of its own color under it so no sliver of the form shows beneath |
| Settings save themselves | No Settings page has a Save button. Switches, segments, chips and selects save at once; typed fields on blur or ↵, with a two-second "Saved" under them. Both mutations (`useUpdateSettings`, `usePluginSettings`) are optimistic: the control moves, and a refusal puts it back and toasts "Not saved — …". Pages bind to the server's values with no draft, so two phones never fight. Sheets and dialogs keep Save and Cancel |
| The Features page | A plugin with a Settings page of its own shows its switch and a row to that page; its fields live there only. This ends two copies of one form with separate unsaved edits. Plugins without a page keep their fields on Features |
| Google's keys | Behind one row under Synced Calendars (**Sign in with Google**: Not set up / Keys saved, Set up / Change) and a sheet, **Google App Keys**. The plugin draws it through a new slot, `settings.features`, and names the spec groups it covers (`ownSettingGroups`), which the generic form leaves out; the Features page special-cases nothing. An empty string clears a secret (the mask keeps it) |
| Secrets in the export | Export everything masks every `secret` plugin setting (`plugin_state.settings_json` through the manifest's `masked()`): Google's client secret used to leave in plain text. Settings of a plugin the build doesn't know leave empty, since its secrets can't be told apart |
| Settings' words | Options read as short as they can, with Never first: Lists' **Clear completed items after** Never · 1 day · 3 days · 1 week; Photos' **Start after** Never · 5 min · 15 min · 30 min · 1 hour and **Change photo every** 15 s · 30 s · 1 min · 2 min · 5 min; Weather's **Temperature unit** Auto · °F · °C; Display's **Return to the calendar after** Never · 2 min · 5 min · 10 min and **Brightness** 60% · 40% · 20% (was How dim: A little · Half · Low). The Theme hint names 7 PM only until the household has a place (it reads the latitude and longitude, as `lib/sun` does); Tasks' last group is **Stars**; a Settings page with one group has no group heading (`Group`'s title is optional) |
| Photos start after 15 minutes | Ten minutes is no longer offered, and the default moved from 10 to 15. A household that had chosen 10 reads as the default, 15, until it picks again: the spec's ordinary fallback for a stored value it can't read, rather than a migration for one number |
| Meals on the calendar, per meal | `calendar_slots` (a multichoice, none by default) replaces the one switch `show_on_calendar`. Settings → Meals draws it as a switch for each meal the family plans, "Show dinner on the calendar"; a meal that's no longer planned loses its switch and isn't drawn, but keeps its choice for when it's planned again. The calendar orders a day's all-day chips by name, as before |
| A plugin's settings across versions | `upgrade_settings(raw, from_version)` on every plugin, a no-op by default. The manager calls it once at boot when the stored `plugin_version` is behind the manifest's, on the stored JSON before unknown keys are dropped, and stores what it returns with the new version. Meals 1.1.0 carries `show_on_calendar: true` to `calendar_slots: ["dinner"]`, so dinner stays on a board that had it. Still no migration for a setting |
| Rows you tap | In Settings a thing you can edit is a row that is the button (`ui/ListRow`, a chevron at its right, named "Edit Mia"): people, the household's calendars, accounts, rewards and routines. The Change buttons beside them are gone, and their sheets are titled "Edit …". Phones & Screens keeps its rows with buttons, since they act (Unpair, Sign out) and open no editor. Outside Settings, a room's own Change buttons stay |
| The color picker | One `ui/ColorPicker` for a person, a calendar and a synced calendar: the colors nobody has first, then the taken ones with whose they are under the word ("Mia's"), still pickable; a person's own color isn't taken for them. It lays out in two columns or four by its own width. The Add panel's event and countdown forms keep their one-row color chips (ADR 0029's Add forms), where "taken" has no meaning |
| An account's sheet | Accounts are rows; a tap opens one sheet with pages (`features/sync/AccountSheet`, the sheet's `step`), never a sheet over a sheet: the account (status, Refresh now, **Sync**, **Show on Kitchen**, Remove account), a synced calendar (Whose, Color), connecting again, and the Remove question. **Sync** lists every calendar the account has with a switch; **Show on …** is named after the paired screen, lists the synced calendars, and is absent while no screen is paired. Switches and chips save at once. An account that needs connecting again offers what fits it: a password or address to type, **Sign in again** for Google's page (not on the kitchen screen), or, for a helper whose key stopped working, removing it and adding it again. "Disconnect" is now "Remove account", and its toast says Removed |
| Recently Removed | A Settings page of its own, after Phones & Screens: it was the last group on Household, under settings it has nothing to do with |
| Erase everything | Settings → Backup → **Start Over**, for a parent on a phone or a computer, never a wall screen (the route refuses a kiosk with 403 and the page doesn't draw it there: a child can reach that screen). It asks first, in two steps: keep a copy (Download everything, or "I have a copy"), then the household password, checked as at sign-in on the same limiter. `meta/erase.py` then makes a verified copy of the database in `backups/pre-erase/` (never rotated; no copy, no erase), stops the plugins, empties every table but `app_meta` in one transaction and puts back a new install's rows, starts every plugin at its default switch and settings (`PluginManager.reset`), deletes the photo files but not `photos/inbox`, moves the auth epoch on and tells every open stream its session ended. No `sunroom erase` command: with the server stopped, restore covers it. The test server's reset shares the table and memory halves, and still keeps `plugin_state` |
| Signed out, or started over | When a device is signed out it asks again whether Sunroom is set up (`handleSignedOut` invalidates the setup status): after an erase the wall shows its welcome screen and a phone the wizard, not a pair code or a sign-in that can't work |
| Downloads go by the device | Backup's downloads, the export and Start Over show unless the device is a kiosk. They used to go by the shell, so a laptop, which draws the wall's shell, had none |
| Settings reach every screen at once | No setting needs a refresh. Core settings already arrived through `settings.changed`. What lagged were plugin settings, which waited for their queries to go stale (up to five minutes for the screensaver's timing): `plugins.changed {id}` now also invalidates that plugin's own queries. Two gaps closed with it: the stream's last position is kept for the page, so the stream a remounted shell opens is replayed what it missed; and the plugin-modules list keeps its previous value while a plugin is switched, so the rail never empties. The only reload left is the one a screen does by itself after the server was updated (ADR 0028). The Pi launcher's `?dimmer=` is its own choice, not a setting |
| What stays with the board | Its own toolbar above the days: Show (the person filter), the plugins' quiet pills, and the Week's tools (the zoom and the layout switch) at the right. Nothing at all with one person, no pill and no tool |

## Consequences

- `household` gains `display_rail_compact` (default off): one migration for the batch,
  `202610121749_household_compact_rail`, with its fixture database built in the same task.
- `RailPlace` is `"header" | "phone"`: a plugin's block by the clock (the weather) draws in the
  header on the wall. The `rail` and `band` places are gone.
- A room's heading is the header's h1, whose name is the title followed by its quiet line
  ("Tasks Today", "Meals Oct 4–10"); a room's `<section>` is named by `aria-label`.
- The Photos room's Start screensaver is an ordinary button on the kitchen screen now, like its
  neighbours: a 64 px primary button would have made the header's row uneven.
