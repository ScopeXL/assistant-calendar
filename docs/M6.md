## How to work through this file

- Read `CLAUDE.md` first: the priorities, the hard rules, the definition of done, the gotchas.
  Then UX §1, §2 and §3 (`docs/UX.md`), and PLAN §7.6, §11.5, §13.6, §15.
- Do the tasks in order. Each one ends with the definition of done (CLAUDE.md): `just check`
  green, `just e2e` green for what it touched, screenshots reviewed when it changed a screen, docs
  updated, a CHANGELOG line under `[Unreleased]`, `just scan` clean, one commit
  (`area: summary` plus the `Co-Authored-By` trailer). Tick the task's box here and note the
  commit, so a session that stops early can be resumed by the next one.
- Never deploy, bump, tag or push: the owner does that with the deploy skill when they ask. The
  release will be 0.7.0 (minor, the family can see every one of these); the skill decides.
- When something here turns out to be wrong about the code, fix the task in the smallest way that
  keeps its intent, say so in the commit message and in the final report. Don't stop to ask unless
  the owner's intent is genuinely unclear.
- Never skip a failing check. Stop and report.

## Decisions (made with the owner on 2026-10-09)

| Question | Decision |
|---|---|
| What the zoom labels mean | A doubling ladder. **24h**: the whole day fits the grid's height, no scrolling. **12h**: half a day fits. **1h**: twice that. **15m**: twice again. See T7 for the numbers. |
| The two week layouts | **Agenda** (today's stacked chips, the default) and **Hours** (the new grid). Settings → Display → "Week layout". |
| Title Case | Titles, headings and navigation labels capitalize each word: page, room, sheet, panel and dialog titles; section headings including the Today panel's; view names, tabs, rail rooms and the header's quick jumps. Action buttons, toasts, hints, row labels, chips, body and error copy stay sentence case. New ADR 0028. |
| "Kid" | The family sees **Child** / **children** everywhere. The stored value `kid` (API, DB, `is_kid_device`, `kid_safe_editing`, `every_kid`) does not change: no migration, no API break. |
| Birthdays | Birthdays become a **core** calendar overlay (`birthdays`), always on, drawn as a real chip in the person's color with a cake mark. Countdowns keeps counting them down (Coming up, the day celebration) but stops drawing them as calendar chips, so nothing shows twice. |
| Live status | One component, five states, told apart by glyph (never color alone), with a tap that says the state in words. It sits top-right of the board header, in the phone's Calendar header, and in About → Connection instead of the words. |
| The updated container | The live-updates `hello` carries the server's version. A page whose built-in version differs shows a toast and reloads itself fresh (service worker unregistered, every cache deleted), waiting for an open editor, a running routine or a pending save, ten minutes at most. One reload per server version, so a stale proxy can't loop it. |
| Add an account | Works on every device. The kitchen screen offers every way except the two that need a file or Google's own page (the helper key and Sign in with Google); for those it shows the phone QR as today. |
| Photos from a browser | A laptop (the display shell, not a paired screen) gets the same Add photos button as a phone. The kitchen screen keeps "from a phone" because a native file dialog has no keyboard or pointer there. |
| Tips | Settings → Display → "Show tips", **off** by default; a 56 px strip under the board on the wall and on laptops; not on phones. |
| Database | One migration for the batch: `household.display_week_layout` and `household.show_tips`. The fixture gotcha below comes first. |

### T7 The Hours layout and the zoom group

- [ ] Done (commit: )

**Owner's note.** The 24-hour vertical week with spacing by time, heights by length, the now
line moving in real time, and a zoom group 24h | 12h | 1h | 15m, default 24h with no scrolling.

**Decisions.** Two layouts, Agenda (today's) and Hours. The household default is
`display_week_layout` (T5); a header switch overrides it for this screen in `displayState`
(`lib/displayState.ts`: `weekLayout: WeekLayout | null`, next to `panelShown`, cleared by
`resetBoard()` after 2 minutes idle, exactly like the Today panel); zoom lives there too
(`hoursZoom: "24h" | "12h" | "1h" | "15m"`, default `24h`, also cleared by `resetBoard()`, which
must count them in its "already initial" test). Phones keep their views (out of scope). The Day
view keeps its collapsed-free-time timeline (out of scope; a candidate for the next batch).
Scrolling the grid has no button twin: a visible scrollbar (`scrollbar-gutter: stable`) and the
24h button, which shows everything, are enough.

**The scale** (`features/calendar/hours.ts`, pure). `pixelsPerHour(zoom, gridHeight, rem)`, where
`gridHeight` is the scroller's height minus the sticky day heads and the all-day band (about
708 px on a 1080p wall, so about 30 px per hour at 24h; about 41 in portrait; less with the tips
strip on): `24h` → `H/24` (the day never scrolls); `12h` → `H/12`; `1h` → `max(2 × 4.5rem,
H/6)` (144 px at Standard: a 30-minute event gets the full two-line chip); `15m` → `max(4 ×
4.5rem, 2 × the 1h value)` (288 px: a 15-minute event gets the full chip). Each step is at least
double the one before. Constants `TAP_REM = 3.5` (56 px, UX §1) and `FULL_CHIP_REM = 4.5` (72 px);
everything in rem so Extra large scales.

**Geometry (all in `hours.ts`, pure, tested).**
- `minuteOfDay("…T15:30:00")` → 930; `minutesToPixels(minutes, pph)`.
- `chipBox(occurrence, day, pph, rem)` → `{ top, visible, height, offset }`: `visible` is the true
  length from `start_local`/`end_local` (never under 2 px; an end at the next midnight counts as
  24:00; multi-day and all-day stay in the band via the existing `byDay()`), `height` is
  `max(visible, 3.5rem)`, and a box that would run past midnight slides up (`offset` is where the
  visible block starts inside it) so it stays 56 px with the block at the true time.
- `chipTier(visible, rem)` → `lines` (≥ 4.5rem: a time row and a title, two title lines from
  6.5rem) · `line` (≥ 3.5rem: title, time, marks on one row) · `title` (≥ 1.75rem: one caption
  line, the display minimum 18 px with 2 px padding; at 24h a one-hour event is about 30 px, so
  this tier is what the default zoom mostly shows) · `bar` (nothing; the accessible name carries
  everything).
- `laneCount(columnWidth, rem, max = 3)` → how many 3.5rem-wide chips with 8 px gaps fit: 3 only
  with the Today panel hidden (233 px columns), 2 at 176 px (1080p with the panel), 1 at Extra
  large portrait. `placeTimed(timed, day, pph, rem, columnWidth)` clusters overlapping chips
  (`clusters()` moved from `DayView.tsx:16-31` into `layout.ts`, generic, DayView imports it),
  lanes them in start order, and when a cluster has more items than lanes shows `lanes − 1` chips
  plus a "+N" box in the last lane spanning the cluster (it opens the Day view). `laneStyle(lane,
